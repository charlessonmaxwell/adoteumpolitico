# Story 2.8 — Página pública "Quando os dados foram atualizados"

**Épico:** 2 · **Status:** Em andamento · **Depende de:** 1.5, 2.6

Pedido do Charlesson (10/11/2026), com modelo aprovado no mesmo dia: uma tela pública de acompanhamento das atualizações.

## Referências
- Rotinas: `.github/workflows/diario.yml`, `presenca-semanal.yml`, `emendas-quinzenal.yml`, `palacio-mensal.yml` e a tarefa semanal de explicações (commits "Explicações populares semanais" na branch `data`).
- Publicação: `.github/workflows/publicar-site.yml`.
- **Nenhuma fonte de dados nova:** a situação vem da API do próprio GitHub (execuções das rotinas e commits da branch `data`).

## Tarefas
1. Cálculo puro da situação de cada fonte (`pipeline/src/situacao/calculo.ts`): estado (em dia, atrasada, ainda não publicado), última atualização, motivo em linguagem simples, próxima tentativa e os últimos 14 dias da rotina diária. Testes em `tests/situacao.test.ts`.
2. Coleta (`pipeline/src/situacao/coletar.ts`): lê a API do GitHub e grava `situacao.json` na pasta de dados do site. Nunca derruba a publicação: sem acesso, grava só que não foi possível conferir.
3. Rotinas diária e semanal de presença passam a registrar o erro como anotação (`::error::`), como emendas e Palácio já fazem, para o motivo aparecer na página.
4. Página `/atualizacoes/` igual ao modelo aprovado, link no rodapé, dados simulados em `site/fixtures/situacao.json`.
5. `publicar-site.yml`: gerar `situacao.json` antes do build e publicar também depois de uma rotina que falhou (os dados continuam os últimos que deram certo; só a página de situação muda).

## Critérios de aceite
- CA1: uma linha por fonte com selo "Em dia", "Atrasada" ou "Ainda não publicado", o que a fonte traz, última atualização, frequência e próxima tentativa (horário de Brasília).
- CA2: quando a última tentativa falhou, aparece o motivo em português simples (ex.: "O site de dados da Câmara não respondeu") e de quando são os números mostrados. Nunca mostra mensagem técnica, endereço ou código de erro.
- CA3: a rotina diária mostra os últimos 14 dias (atualizou / não atualizou / não rodou).
- CA4: fonte sem atualização dentro do prazo previsto aparece como "Atrasada", mesmo sem falha registrada.
- CA5: se a API do GitHub não responder, a página continua no ar dizendo que não foi possível conferir agora; a publicação não falha por isso.
- CA6: sem opinião nem culpa: textos fixos, só fatos.
